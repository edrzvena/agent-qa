# Agent QA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Python AI agent that explores a web app in a real browser, reports technical and functional bugs with evidence, and is benchmarked against a dummy app with known bugs.

**Architecture:** A Claude tool-use loop drives a Playwright browser wrapper. A passive detector records console/network/crash events in parallel with no LLM involved. A reporter merges detector events and agent-reported bugs into HTML and JSON. A Flask dummy app with flag-toggled bugs and a `bugs.json` ground truth feeds an eval harness that computes recall and false positives.

**Tech Stack:** Python 3.11+, `anthropic`, `playwright` (sync API, Chromium), `flask`, `pytest`, `python-dotenv`.

**Spec:** `PRD.md` (project root)

## Global Constraints

- Language Python; package name `agent_qa` under `src/`, folder `agent-qa/`.
- LLM is Claude via the Messages API with tool use. Default model `claude-sonnet-5-5`, overridable by `AGENT_QA_MODEL` env var or `--model`.
- API key read from `ANTHROPIC_API_KEY` in `.env`. Missing key stops the CLI with a clear message before any run starts.
- Agent tools are exactly: `goto`, `click`, `fill`, `get_page_state`, `report_bug`, `finish`.
- Defaults: max steps 30; max cost per run in USD configurable (default 1.00); same action repeated 3 times in a row triggers a forced strategy change, then stop.
- `report_bug` requires: title, steps (list), actual, expected. Screenshots and detector logs are attached by code, never requested from the LLM.
- Browser tools return concise text (visible text plus interactive-element list), never raw HTML.
- v1 covers technical and functional bugs only. No visual/a11y checks, no regression-test generation, no web UI.
- Dummy app has 12 bugs (B01-B12), each toggled by flag, ground truth in `dummy_app/bugs.json`.
- Eval reports recall on the full-bug app and false positives on the clean app.
- The user handles all git operations. The agent never runs `git`.
- Unit tests never call the real API. Real-API evals live in `evals/` and are not part of `pytest`.

## Review Focus

- Target URL unreachable or not a valid URL: CLI exits non-zero with a readable message, no traceback. (Task 7)
- Selector matches zero or several elements: tool returns an error string to the agent and the run continues. (Task 4)
- Page with no interactive elements or a huge text body: state is still returned, truncated to a fixed length. (Task 4)
- A JS `alert`/`confirm` dialog appears: it is auto-dismissed and recorded, and does not hang the run. (Task 3)
- Claude API errors (rate limit/overload) or cost cap reached: retry with backoff, then end with a partial report marked `truncated`. (Task 6)
